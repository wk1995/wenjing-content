# 文镜去 AI 味润色

将“去 AI 味”视为可读性和作者声音的编辑工作，不是规避 AIGC 检测。保留原文已核验的事实、来源、立场和篇幅约束；不得编造个人经历、数据、引用或测试结果。

## 开始前

1. 阅读目标稿，以及同项目的 `brief.md`、`plan.md` 和 `sources.md` 中与该稿有关的部分。
2. 有作者过往成稿时，优先用其作为声音样本；没有样本时，使用朴素、具体、克制的中文表达，不虚构个性。
3. 阅读 [检查表](references/checklist.md)。涉及事实时，保持原有引用；需要补充或改动易变事实时，先核验一手来源。

## 选择模式

| 用户意图 | 执行方式 |
| --- | --- |
| “检查 / 标出问题 / 不要改” | `audit`：按严重程度列出问题、原句与理由，不改文件。 |
| “优化 / 去 AI 味 / 润色” | `edit`：默认模式；只改有问题的句段，保留已自然的表达。 |
| “重写，但保留观点” | `rewrite`：保留信息结构和事实，重写全文。 |

用户没有指定时，先采用 `edit`，不要为了“更自然”而整篇推倒重来。

## 编辑流程

1. 找出具体问题：空泛判断、夸张意义、套话转折、均匀句式、概念堆叠、机械排比、无来源的“专家认为”，以及不属于作者的假装亲历。
2. 先改结构，再改词。让每段承接上一段，并围绕一个读者问题推进；不能只把“高级词”换成同义词。
3. 用任务、场景、限制和可验证动作替换抽象判断。保留必要术语，但第一次出现要接生活语言或例子。
4. 调整节奏：长短句、段落长度和标题密度都要有变化；不要把每段都写成“提出观点 → 三点解释 → 升华”的同一模版。
5. 需要第一人称时，只写作者已经提供或可确认的观察。可以诚实表达“我也在学习 / 仍在核验”，但不要用空泛自谦代替信息。
6. 做第二遍检查：删掉多余总结、重复结论和读者已经能自行推出的话；确认改动没有改变事实强度、适用范围或原意。

## 公众号专项要求

- 先给读者熟悉的画面，再解释概念；一篇只解决一个主要问题。
- 将“很重要、值得关注、标志着、正在改变一切”等无证据判断改为具体影响，或删掉。
- 保留真实的不确定性：机型、系统、地区、版本或体验差异必须写清条件。
- 互动结尾要与正文有关，例如征集设备、场景或实际问题；不要使用空泛的“欢迎留言讨论”。
- 不要为降低检测分数故意制造错别字、病句、虚构细节或随机化表达。

## 交付与存放

1. 说明使用的模式、主要问题和改动原则。
2. `audit` 只交付问题清单；`edit`/`rewrite` 交付成稿与简短改动摘要。
3. 修改公众号稿时，将成稿放在 `projects/{project}/wechat/`；将本次的写作判断、来源变更、标题或配图调整写入同项目 `sources.md`。
4. 对即将粘贴到微信编辑器的版本，移除 front matter 和内部资料编号，只保留读者可见的标题、正文和来源。
