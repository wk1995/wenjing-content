# 短视频脚本质量量表

在优化已有脚本时使用本量表；不必机械打分，但要说明最影响成片的 3–5 项问题。

| 维度 | 好的信号 | 常见问题 | 优化动作 |
| --- | --- | --- | --- |
| 前三秒钩子 | 明确对象、矛盾或收益；第一帧能独立理解 | 寒暄、泛泛自我介绍、结论来得太晚 | 把问题、反差、结果或关键动作前置 |
| 核心信息 | 一条视频只承载一个主结论 | 多个卖点并列、没有主次 | 保留一个承诺，其余删减或拆为系列 |
| 证明路径 | 演示、前后对比、步骤、场景或可信事实支撑结论 | 只下结论、堆形容词 | 把“为什么可信”放在结论之后尽早呈现 |
| 口语感 | 句子短、可自然停顿、有具体对象 | 书面长句、名词堆叠、抽象套话 | 一句只表达一个动作或判断，换成口头表达 |
| 节奏 | 每 2–5 秒出现新的信息、动作或画面变化 | 同一画面长讲、转折缺失 | 增加动作、特写、结果镜头或信息卡，但不无意义快切 |
| 画面证据 | 画面展示过程、结果、细节或使用场景 | 口播和画面重复，或画面不能证明内容 | 为每个关键判断安排一个可见证据 |
| 屏幕文字 | 只强调关键词、数字或复杂专名 | 字幕复制整段口播、文字太多 | 保留观众扫一眼仍能理解的短语 |
| CTA | 与内容结果自然衔接、动作明确 | 生硬求赞、CTA 与主题无关 | 给出一个低摩擦动作：评论、收藏、查看或下一步 |

## 优化检查

- 先保留已核验事实和用户明确要求，不为追求节奏改变承诺边界。
- 删除不能推进理解、证明、情绪或行动的句子。
- 将抽象判断转成可见动作或可感知场景，例如把“效率很高”改为具体的前后差异或使用步骤。
- 区分观众需要听到的内容与需要看到的内容；同一句口播不必完整出现在屏幕上。
- 修改后重新估算时长，确保口播、动作和转场能在目标时长内完成。
