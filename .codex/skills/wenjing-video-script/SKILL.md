# 文镜视频脚本

将一个内容 brief 变成可拍、可说、可剪的短视频脚本，或将已有脚本优化成更清楚、更有节奏的版本。默认用中文输出；将口播、画面和屏幕文字分开处理。

## 文件归属

- 具体内容必须写入 `projects/{project-slug}/`，不能放入本 Skill 或全局目录。
- 需求、受众、产品事实和内容边界写入项目 `brief.md`；可引用事实、标题、参考素材和视觉建议写入 `sources.md`。
- 抖音成稿写入 `douyin/script.md`，逐镜分镜写入 `douyin/storyboard.md`。其他平台先确认项目内已有的对应平台入口，再创建成稿。
- 对已有稿件的优化，保留原文件；将优化后的可发布版本写回对应平台成稿，并在 `plan.md` 或 `sources.md` 简要记录改动目标。

## 选择工作模式

1. **新建脚本**：用户提供选题、产品/观点或素材，希望从零写口播稿、脚本或分镜。
2. **优化脚本**：用户给出现有口播稿、粗剪台词、分镜或字幕，希望优化开头、节奏、表达、转化或可拍性。
3. **生成后优化**：先生成结构，再根据用户的保留要求、时长或素材限制进行第二轮改写。

若缺少关键信息，优先根据已有项目文件补全。仍无法判断时，仅询问最影响结果的一项：目标受众、内容目标、时长、发布平台或必须保留的信息。用户未指定时，默认制作一条 30–45 秒、竖屏、单一核心观点的中文短视频。

## 新建脚本工作流

1. 明确受众、目标（认知、种草、转化、讲解或互动）、时长、平台、人物/产品、可用素材、CTA 与合规边界。
2. 只选一个核心承诺或观点；不要把多个平行卖点塞进同一条短视频。
3. 设计节奏：`0–3 秒钩子 → 场景/问题 → 证明或过程 → 核心结论 → CTA`。钩子必须同时包含可说的矛盾、收益或问题，以及可暂停理解的第一帧画面。
4. 为每个节拍分别写口播、画面动作/素材、屏幕文字和预计时长。让画面补充或证明口播，不要逐字重复。
5. 按正常语速检查时长：中文口播默认每秒约 3.5–4.5 个汉字；留出动作、停顿和转场时间。
6. 审核事实与合规：不要虚构数据、体验、价格、功效、资质或用户反馈；不确定的事实标记为待核验，不写成确定承诺。

## 优化现有脚本工作流

1. 先提取原稿不可丢失的内容：核心意图、事实、品牌语气、必须出现的卖点、可用镜头和 CTA。
2. 阅读 [脚本质量量表](references/script-quality-rubric.md)，按钩子、清晰度、信息密度、画面证据、口语感、节奏与 CTA 诊断问题。
3. 判断改动幅度：
   - **轻度**：保留结构，只压缩空话、修正口语、增强首句或补足画面动作。
   - **中度**：保留核心观点，重排信息顺序，让证明早于结论，或拆分一句多个卖点。
   - **深度**：仅保留事实和目标，重写开头、叙事路径和分镜；明确说明哪些元素被替换及原因。
4. 先给出简短诊断和修改策略，再给出完整优化稿。除非用户只要成稿，否则列出 3–5 个关键修改点，让改动可复核。
5. 不要仅替换“高级”“爆款”“震撼”等形容词。每一处优化都要改善观众能看见、听懂或愿意继续看的具体信息。

## 默认交付

按用户需求裁剪；未指定格式时按以下顺序交付：

1. 创作目标、受众与必要假设
2. 脚本结构与前三秒设计
3. 完整口播稿（含时间段）
4. 分镜表：`镜号｜时长｜画面/动作｜口播｜屏幕文字｜拍摄或剪辑提示`
5. 优化任务额外提供：关键问题、改动策略和保留项
6. 事实待核验项与合规风险

## 与其他 Skill 协作

- 抖音投放、竞品拆解或平台合规要求更强时，转用 `$wenjing-douyin-script`；本 Skill 负责通用脚本生成与优化方法。
- 分镜确定后需要生成 Seedance 镜头时，再调用 `$seedance-20`。传递已批准的镜头目标、时长、画幅、参考素材角色和连续性要求；不要让 AI 视频提示词反过来改变已确定的内容目标与合规结论。
