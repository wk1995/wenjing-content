## 1. 产品定义

本产品是一条 AI 唱歌内容生产链路，不是一个新的歌声模型，也不是声音克隆工具。

v1 要证明一件事：作者可以在可追溯、可合规的前提下，做出一首原创 AI 歌曲，并留下足够的记录，使这次制作以后能够复述、重做或改写成内容。

## 2. 背景

开源项目同时覆盖整首生成、按谱演唱和音色替换，名称接近，误用成本高。直接做翻唱或部署模型，会把版权、声音权利和本机环境问题混进第一次实验。

可行性分析的结论是：先用云端能力做原创短歌，本地开源模型只作为下一阶段候选。本 PRD 按这个结论收缩 v1。

## 3. 目标

### 产品目标

- 产出 1 首 30–90 秒的原创歌曲 demo，包含歌词、风格说明和音频结果。
- 每次生成都能回查工具、模型或接口、日期、提示词和已知限制。
- 成品可以明确标注为 AI 生成，且不依赖未授权的歌曲或真人音色。

### 成功标准

- 作者听完后认为主歌和副歌能区分，歌词听得清。
- 记录足以让另一个会话按同一说明重做，而不需要依赖聊天记录。
- 没有使用名人音色、未授权原曲或未标明的 AI 人声。

不要求达到商业发行音质，也不要求本地离线运行。

### 非目标

- 训练或微调自己的歌手模型。
- 部署 RVC、Applio、SoulX-Singer 或 DiffSinger。
- 制作公众号、小红书、抖音或掘金成稿。
- 比较全部云端音乐产品并给出排行榜。
- 承诺生成内容的著作权归属。该项以所用服务当时的条款为准。

## 4. 用户与场景

v1 只有一个用户：本仓库的内容作者。

主场景：给定一个主题，得到一段可试听的原创歌曲，并决定它是否值得继续改、继续生成或写成内容。

不做的场景：替他人克隆声音、批量生产翻唱、对外提供生成服务。

## 5. 范围

### v1 包含

- 选定一个云端音乐生成入口。候选是已检索到的 Beatra、青榄和 MXAPI / Suno；选定前先确认账号可用。
- 一次完整制作：主题、歌词、风格、生成、听评、记录。
- 失败也要记录。连续 3 次不能得到可听结果，即停止并回写原因，不换路线硬做。

### v1 不包含

- 安装社区变声 Skill。
- 本机运行 ACE-Step 1.5。该项是 v1 通过后的可选验证。
- 平台发布和数据复盘。

## 6. 制作流程

1. 选择主题。主题必须能用原创歌词表达，不指向特定歌手或现成歌曲。
2. 写 8–16 行歌词，并写出风格、情绪、语言和大致时长。
3. 使用选定的云端入口生成。提示词和参数保留原文。
4. 作者试听，只记录可重复的问题：跑调、吐字不清、结构断裂、伴奏压过人声。
5. 最多修改歌词或风格后再生成 2 次。
6. 选定一版，把来源、提示词、日期和听评写入 `sources.md`。音频文件不提交。

状态、允许的跳转和终态见 `doc/state-machine.md`。机器可读定义见 `doc/production-state-machine.yaml`。流程文字与状态机冲突时，以状态机迁移表为准，并同时改正文。

## 7. 需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| R1 | 制作前写明主题、语言和时长 | `sources.md` 有对应条目 |
| R2 | 歌词为原创，不复述在先歌曲的主歌或副歌 | 条目中标明“原创歌词” |
| R3 | 生成时记录工具名称、接口或模型标识、日期 | 三者缺一则不算完成 |
| R4 | 保留实际使用的提示词 | 不改写成事后总结 |
| R5 | 听评只写听到的问题，不把未测项目写成事实 | 不出现未运行模型的音质结论 |
| R6 | 对外描述必须能标明 AI 生成 | 记录中预留发布标识用语 |
| R7 | 不提交音频、权重和密钥 | `git status` 不出现这些文件 |

## 8. 内容与权利约束

- 不上传他人的歌声作为音色样本。
- 不上传受版权保护的歌曲作为翻唱源。
- 风格描述可以指向流派，不点名模仿一位在世或已故歌手的声音。
- 若服务条款不允许公开使用，demo 只作内部验证，不进入平台目录。
- 生成失败、额度不足或条款不明确时，停止发布流程，不换成来源不清的社区模型。

## 9. 数据与文件

仓库内只新增文字记录。音频保存在仓库外，路径可以记在 `sources.md`，但路径本身不能包含密钥或账号信息。

一次合格记录至少包含：主题、歌词、风格提示词、工具、日期、试听结论、是否允许公开。

## 10. 里程碑

| 阶段 | 完成定义 | 状态 |
| --- | --- | --- |
| M0 文档 | 可行性分析、PRD、状态机和来源记录可审阅 | 本次完成 |
| M1 入口确认 | 选定一个云端入口，并确认账号、价格和使用权 | 未开始 |
| M2 试做 | 完成最多 3 次生成，留下 1 个选定版本或 1 份失败记录 | 未开始 |
| M3 决策 | 决定停止、改写内容，或另行验证 ACE-Step 1.5 | 未开始 |

M3 不是 v1 的必达能力。v1 在 M2 的记录完成时结束。

## 11. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 云端账号或额度不可用 | 听不到 demo | 停止，不临时改用未评估工具 |
| 生成听感不稳定 | 无法判断主题是否成立 | 最多 3 次，其后记录失败 |
| 服务条款限制公开 | 不能发到平台 | 只保留内部记录 |
| 把音色替换误当成 v1 | 引入版权和声音权利问题 | PRD 明确排除 |
| Mac 无法运行后续本地模型 | 技术稿缺少实测 | 不写部署文，直到实际跑通 |

## 12. 开放问题

- M1 最终用哪一个云端入口，取决于账号是否已经可用。
- 生成内容能否用于公众号或短视频，取决于该入口的条款和目标平台规则。
- 本地验证是否值得做，取决于 M2 的听感是否足以支持后续内容，而不是取决于开源项目的 star 数。
