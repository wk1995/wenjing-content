## 结论

可以做，但 v1 不应该自研模型，也不应该把“AI 翻唱名人”当作默认路线。

建议的第一阶段是：用云端音乐生成验证选题和听感，只做原创歌词和原创旋律；本地开源模型里，整首生成优先考察 ACE-Step 1.5。按谱演唱和音色替换都可行，但前者制作成本高，后者的版权和声音权利风险最高，不进入 v1。

本仓库负责记录需求、来源、提示词和成稿。模型权重、原始音频和生成结果不提交进 Git。

## 问题定义

“AI 唱歌”在公开项目里实际是三件不同的事：

| 路线 | 输入 | 输出 | 典型项目 |
| --- | --- | --- | --- |
| 整首生成 | 风格描述，可选歌词 | 带伴奏和人声的歌曲 | ACE-Step 1.5、YuE、云端 Skill |
| 歌声合成 | 歌词加旋律或 MIDI | 指定唱法的人声 | SoulX-Singer、DiffSinger |
| 音色替换 | 已有干声，加目标音色 | 用另一个声音唱同一段旋律 | RVC、Applio、Seed-VC |

三条路线不能互相替代。能写歌，不代表能按谱唱准；能换音色，不代表能从歌词创作一首新歌。

## 技术可行性

### 整首生成：可行，且最适合当前目标

ACE-Step 1.5（S5）在 2026-10 仍在更新，MIT 许可，仓库明确支持 Mac。YuE（S7）同期也在更新，Apache-2.0，仓库说明包含零样本翻唱。两者都足以作为“从文字到一首歌”的候选。

云端 Skill 同样可行，而且不需要本地 GPU。WorkBuddy 当前能检索到写歌、音潮工作流和经网关调用 Suno 的 Skill（S13）。MiniMax 官方仓库提供 `minimax-music-gen`（S12），但是 API 产品，不是可离线模型。

限制：仓库自述的音质和速度不能当成已验证。云端结果还受账号、额度和服务条款约束。

### 歌声合成：技术上可行，内容生产上偏重

SoulX-Singer（S4）和 DiffSinger（S8）解决的是“给定旋律后人怎么唱”。这条路线适合虚拟歌手和可控演唱，不适合作为第一首 demo 的路径。

DiffSinger 通常还要准备标注数据或声库。SoulX-Singer 宣称零样本，但本机能否运行、参考音频需要多长，本次都没有验证。

### 音色替换：工具成熟，默认场景不可用

RVC（S1）和仍在维护的 Applio（S3）是这条路线里最成熟的工具。Seed-VC（S10）可以不先训练，但许可证是 GPL-3.0，且 2025-04 后没有新推送。so-vits-svc（S2）star 很多，但 2023 年后基本停更。

工具成熟不等于这条路线适合公开内容。输入通常是别人的歌曲干声，输出又使用特定人的音色。没有歌曲授权和声音授权时，不能作为本项目的发布物。

## Skill 可行性

有现成 Skill，但没有一个开源 Skill 等于“在 Mac 上离线完成 AI 唱歌”。

| 类型 | 代表 | 能否直接用 | 约束 |
| --- | --- | --- | --- |
| 云端写歌 | Beatra、青榄、MXAPI / Suno | 可安装后调用 | 需要对应服务账号，结果和价格未验证 |
| 官方音乐 Skill | MiniMax `minimax-music-gen` | 需按仓库方式接入，并配置 API Key | 生成不离线；仓库仍是 Beta |
| 社区变声 Skill | 公开目录中的 RVC voice-changer | 不建议安装 | 来源分散，且解决的是变声，不是本项目 v1 |

`buddy-sings` 依赖 Claude Code 的宠物配置和 MiniMax 音乐 Skill，不适合作为 WorkBuddy 内容项目的主流程。

## 运行环境

当前工作机是 macOS。这会影响路线选择：

- ACE-Step 1.5 的仓库说明包含 Mac，是本地路线里唯一可以优先尝试的候选。
- RVC / Applio 的常见高质量路径依赖 NVIDIA CUDA。Mac 不是这条路线的有利环境，本次不把它列为 v1。
- SoulX-Singer、YuE、DiffSinger 是否能在这台 Mac 上完整跑通，尚未核验。

因此“本地可复现”目前只是候选，不是已证实能力。v1 若要听到结果，应先走云端生成。

## 合规可行性

这是本项目的硬约束，优先级高于音质。

可以做：

- 自己编写的歌词、自己描述的风格、工具生成的原创伴奏和人声。
- 明确标注内容由 AI 生成。
- 使用 MIT 或 Apache-2.0 工具做实验，并保留来源记录。

不能作为默认工作流：

- 克隆真实歌手、演员或其他可识别自然人的声音。
- 使用未授权歌曲的干声、伴奏或旋律做翻唱后发布。
- 把生成结果说成真人演唱，或隐去 AI 生成标识。
- 将 GPL / AGPL 项目的代码并入本仓库后再分发。本仓库只记录链接和选型，不复制其代码。

云端服务还有单独的条款。Suno、音潮、MiniMax 对生成内容的使用权可能不同，使用前要看当时条款，不能沿用开源许可证的判断。

## 和本仓库的匹配

`wenjing-content` 是内容仓库。它适合保存：

- 需求、方案、来源和提示词。
- 可复用的内容结论。
- 平台成稿。

它不适合保存模型权重、训练数据、下载的原曲和大体量音频。生成文件应放在项目外或本地未跟踪目录，只把必要的文字记录写回 `sources.md`。

## 建议

v1 采用云端原创生成，只验证“能否稳定得到一首可听、可说明来源的短歌”。

通过后再做一次 ACE-Step 1.5 的本机试运行，用来判断本地路线是否值得写成技术内容。音色替换和名人翻唱不进入后续计划，除非同时具备歌曲权利和声音权利。

## 待核验

- 选定云端 Skill 的账号、价格、生成内容权利和失败时的退款或重试规则。
- ACE-Step 1.5 在当前 Mac 上的实际内存占用和一首歌的耗时。
- SoulX-Singer 的 Mac 支持范围。
- 目标发布平台对 AI 生成音乐的标识和上传规则。
