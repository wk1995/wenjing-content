# keep-up-with-ai 项目 Brief

## 背景

- 为什么要做这个项目：AI 消息太多，GitHub 新库、论文和产品发布、大厂动作叠在一起，普通人很难判断今天真正值得看的是哪一条。这个项目把「筛一条、讲清楚、三个平台同一天发出」做成固定栏目。
- 触发来源：2026-10-15 主题调整。原定位是「普通研发如何跟上 AI 资讯」，现改为资讯日更，不再以个人焦虑记录为主线。
- 期望解决的问题：每天用一条内容回答「今天 AI 圈最值得知道的是什么」，周一和每月 1 日再把刚过去的一周、一个月收成趋势。

## 目标

- 内容目标：日更覆盖三类资讯——GitHub 开源库介绍、AI 行业前沿技术、各大厂 AI 动态。每周一另发周报，每月 1 日另发月报；总结不替换当天日报。
- 业务目标：在抖音、快手、微信公众号建立稳定更新的 AI 资讯栏目。初期先把更新节奏跑顺，不把变现当当前目标。
- 学习或沉淀目标：每条资讯留下可回查的来源、核验日期和一句话结论，周报月报能直接复用这些记录。

## 受众

- 核心读者/观众：关注 AI、但没有时间追全部信息源的人。开发者想看库和前沿技术，普通观众想看大厂和「这东西能干嘛」。
- 已有认知：知道 AI 很火，不一定熟悉模型、框架或论文术语。
- 主要痛点：信息太碎，分不清新闻、演示和真进展；看到仓库名或发布会标题，不知道要不要花时间。
- 可能误解：以为日更等于把热榜搬一遍；以为三个平台应该发三件不同的事。

## 内容边界

- 必须覆盖：
  - GitHub 开源库：这个库是什么、解决什么问题、和已有工具差在哪、仓库与许可证从哪看。
  - 行业前沿技术：论文、模型、框架或工程方法里，今天值得知道的一个变化，以及它还不能做什么。
  - 大厂 AI 资讯：OpenAI、Anthropic、Google、Meta、Microsoft、苹果、英伟达，以及阿里、字节、腾讯、百度、华为等已公开的发布、开源和产品动作。
- 暂不覆盖：个人追赶日记、算法课、论文逐段精读、纯股价或融资八卦、与当天主题无关的工具清单。
- 不能说或需要谨慎表达：未核验的「最新、最强、第一、免费、已上线」；把某一家的接口、价格、配额或地区可用性说成全行业都这样；未公开的内部消息；把演示视频说成已可复现。

## 三类资讯怎么选

每天只主推 1 条。优先级：

1. 当天有官方发布、且影响面明确的大厂或模型消息。
2. 有仓库、论文或技术报告，能讲清「新在哪里」的前沿技术。
3. 能说清用途、许可证和成熟度的 GitHub 开源库。

三类都不硬凑。材料只有二手转载、缺一手链接时，宁可不发这条，也不把日历填满。

## 平台范围

| 平台 | 是否制作 | 目标 |
| --- | --- | --- |
| 微信公众号 | 是 | 日更短文可回看；周总结、月总结写完整 |
| 抖音 | 是 | 同一条资讯的快节奏短视频，前 3 秒给结论 |
| 快手 | 是 | 同一条资讯的口语短视频，少黑话，先讲能干嘛 |
| 小红书 | 否 | 本项目不做 |
| 掘金 | 否 | 本项目不做 |

三个平台同一天讲同一条事实。差异只在时长、语气和信息密度，不各写各的新闻。

## 交付物

- `brief.md`：栏目定位、三类选题和平台边界
- `plan.md`：日更 / 周总结 / 月总结的做法和风险
- `sources.md`：单条来源、核验日期、大纲和标题池
- `shared/outline.md`、`shared/key-points.md`：三条平台共用的结构和表达
- `research/topic-research.md`：选题判断；竞品仍待补
- 平台成稿：按 `README.md` 的日期命名写入 `wechat/`、`douyin/`、`kuaishou/`
