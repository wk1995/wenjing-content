# 资料与结构

## 资料原则

- 优先使用仓库 README、Release、官方博客、发布公告、论文、技术报告和产品页。
- 每条日更、周报、月报都记录来源标题、链接、发布时间和核验日期。
- 「最新」「最近」「本周」「本月」必须对应具体日期，不写无法回查的时间。
- 二手文章只用于发现线索，不单独支撑关键事实。
- 价格、接口、模型 ID、配额、地区可用性、许可证，只描述被核验的那一家、那一版。
- 三个平台共用本文件里的事实。平台稿不新增这里没有的数字。
- 单条大纲、标题池和配图建议记在本文件；`wechat/`、`douyin/`、`kuaishou/` 只放成稿。

## 每天扫描的信源

| 前沿技术 | 论文、技术报告、官方研究博客 | 只看二手解读 |
| 大厂 AI | 厂商官方发布公告和产品页 | 未署名爆料、转载截图 |

## 黑话对照

写稿时把术语翻译成下面这种长度，不单独做概念栏目。

| 概念 | 一句话 |
| --- | --- |
| 开源库 | 别人把代码公开出来，你能看、能按许可证使用 |
| Release | 作者标出来的一个正式版本，不等于仓库里每天的提交 |
| 许可证 | 规定你能不能商用、要不要保留署名 |
| 模型 | 完成对话、识图或生成的那套 AI 程序 |
| 内测 | 只有一部分人能用，不等于正式上线 |
| 正式发布 | 官方按公开规则提供，仍可能分地区和分版本 |

## 单条内容结构

### 日更

- 输出文件：`wechat/daily/YYYY-MM-DD.md`、`douyin/daily/YYYY-MM-DD-script.md`、`kuaishou/daily/YYYY-MM-DD-script.md`
- 状态：未开更

目标：观众看完能复述「今天这一条是什么、新在哪里、自己要不要现在跟」。

标题池只是角度，具体标题等当天选题再写：

1. 今天 AI 只看这一条
2. 这个开源库今天值得打开看一眼
3. 这家大厂今天发布的，先别理解成都能用
4. 今天这条技术新闻，新的其实只有一点

大纲：

1. 结论
2. 属于开源库、前沿技术，还是大厂动态
3. 一句人话
4. 和旧版本或同类的差异
5. 谁用得上，谁先不用管
6. 链接、核验日期、不能下的结论

### 周报

- 发布时间：每周一，和当天日报一起发
- 覆盖范围：刚结束的周一至周日
- 输出文件：`wechat/weekly/YYYY-Www.md`，短视频用发布当天日期脚本

大纲：

1. 这一周只留 3–5 条
2. 开源库、前沿技术、大厂动态分组
3. 本周补记
4. 这周继续盯的一个问题

### 月报

- 发布时间：每月 1 日，和当天日报一起发
- 覆盖范围：上一整月
- 输出文件：`wechat/monthly/YYYY-MM.md`，`YYYY-MM` 是被总结的月份，不是发布月

大纲：

1. 这个月三个变化
2. 还值得跟的
3. 可以放下的
4. 这个月只观察的问题

1 日若是周一，月报、周报、日报分三篇写，不并成一篇。
