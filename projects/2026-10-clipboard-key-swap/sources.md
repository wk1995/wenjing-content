## 资料原则

- 这篇只使用 2026-10-17 那次 WorkBuddy 对话里已经跑出来的观察。没有在本次写作中重做取证。
- 对话导出页是用户给出的链接，正文以页面制品 `conversation-data.json` 为准，不凭记忆补事实。
- 易变信息（哪个进程、哪条任务、哪一次触发比例）都标了对话里的实验条件，不能改写成「所有 Windows 都这样」。
- 平台成稿和入库归档里的密钥一律写成 `hlg_[REDACTED]`。未打码原文只留在本机 `_downloads/`，该目录被 gitignore，不提交。

## 单篇内容结构

### clipboard-key-swap-01

- 输出文件：`wechat/article.md`、`douyin/script.md`、`channels/script.md`
- 平台：微信公众号、抖音、微信视频号
- 状态：drafting

### 目标

- 把一次剪贴板被改写的排查，写成别人能跟着判断的故事。

### 目标读者

- 复制 API Key 时发现粘贴内容变了的人。

### 核心观点

> 先看是不是「复制之后又被写了一次」，再用对照实验找写入者；签名正常的系统进程也可以只是外壳。

### 标题池

1. 我复制了一串 API Key，粘贴出来的却是另一串
2. 不是手滑：剪贴板在 200 毫秒里被换掉了
3. 关掉编辑器还在发生，问题就不在编辑器里
4. 系统进程是正版的，里面的代码不是
5. 一条伪装成系统任务的计划任务，把密钥换了半年

### 摘要

- 复制特定形状的密钥时，Win+V 里会多出一条头尾相同、中间被改过的新值。WorkBuddy 用对照实验排除了编辑器和远程工具，把写入定位到被注入的 `UserAccountBroker.exe`，再沿计划任务和时间戳追到 2026-04-20 的一份第三方安装包。

### 大纲

1. 发现：一次复制，历史里多出两条。
2. 排查：监听写入时间、格式和所有者，用挂起对照排除软件。
3. 溯源：内存里的手工映射模块，以及半年前的计划和注册表。
4. 修复：断网、换密钥、清持久化，并说明清理不等于已经干净。

### 实践或案例插入点

- 用「有没有 HTML Format、所有者是不是空的」区分人的复制和后台改写。
- 用「全新的同形状字符串也会被改」证明不是一对一替换表。

### 排版与素材建议

- 公众号用两张表：复制时间线、溯源时间线。不要截含完整密钥的 Win+V。
- 视频第一帧用打码后的前后对比，字幕只留「56 位进去，55 位出来」。

## 不确定信息

- 对话使用的模型：第一轮 grok-4.7，其后各轮记录为 Deepseek-V4.1-Flash。用户口头说的是 workbuddy + deepseek v4.1-flash，与导出元数据一致，除了开场那一轮。
- `UserAccountBroker.exe` 文件哈希与 WinSxS 一致、签名有效，这条是对话中的检查结论，本次写作没有复核二进制。
- 触发并不每次都发生。自动写入比手动 Ctrl+C 更不稳定。文章里的「稳定」只指用户手动复制那条路径。
- 清理后会不会复现、Defender 离线扫描能否检出，对话没有结果。
