## 口播稿

1. 开头：我复制了一串 API Key，粘贴出来是另一串。头尾还在，中间被换了。历史记录里能看到，新的那条比我按下复制晚了不到一秒。

2. 它是什么：不是输入法，也不是编辑器多复制了一次。我那一次带着正常格式。后面跟着的那条只有纯文本，而且说不出是哪个窗口写的。它专门认这种密钥的形状。普通文字不动，一条从没出现过的同形密钥，照样被换成新的。

3. 新在哪里：关掉 WorkBuddy、飞书、代码编辑器，退出远程工具，它还在。把一大堆第三方软件暂停，也还在。只有按住一个名字很系统的进程，改写才停。那个文件签名是微软的，磁盘上的文件也没被换掉。被塞进去的是进程内存里的代码。

4. 谁用得上：你要是经常复制 API Key，打开剪贴板历史看一眼。如果同一次复制后面总跟着一条很像、但不相同的记录，先别再在这台电脑上签发新密钥。

5. 证据和边界：这次追到半年前一份从跳转站下来的安装包。它留了两条藏在系统任务目录里的计划任务，实际跑的是用户目录里一个没有签名的小程序。这是一台电脑上的一次排查，不是说所有同名软件都有问题。对话结束时，清理还没做，所以我不能说已经修好了。

6. 结尾：顺序不要反。先断网，再去另一台设备把密钥作废，然后才是删那些开机项。完整的发现、排查、溯源和修复边界，在公众号长文里。
