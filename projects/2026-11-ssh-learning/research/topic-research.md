# SSH 新手学习需求与资料调研

## 调研目标

确定如何用用户已有的 Mac 和 Windows 教会基础 SSH，而不把购买服务器或网络改造变成前置条件。服务对象是用户本人，暂不面向内容平台发布。

## 选题背景

主题由用户明确提出。用户自述零基础、公司用 Mac、家里有 Mac 与 Windows，当前没有远程服务器。这些是用户提供的条件，不代表已核对设备状态。

## 受众洞察

| 当前起点 | 需要先解决的困惑 | 对应设计 |
| --- | --- | --- |
| 不熟悉命令行 | 终端、Shell、SSH 是不是同一个东西 | 概念表与只读命令 |
| 没有服务器 | 是否必须先花钱才能练习 | 家庭 Mac 自连接 |
| 有两种系统 | 窗口在 Windows，命令为什么能操作 Mac | 家庭跨设备登录 |
| 不熟悉密码学 | 公钥、私钥、指纹与密码的关系 | 先讲两个身份，再做独立密钥练习 |
| 公司和家里两处使用 | 家庭 IP 为什么不能直接在公司连接 | 把网络可达性独立成篇 |

## 一手资料结论

- 苹果提供通过“远程登录”启用 SSH/SFTP 并限定用户的入口，适合家庭 Mac 实验。
- Windows 提供 OpenSSH 客户端组件；组件是否已安装须在实际设备检查。
- OpenSSH 支持公钥认证、客户端别名、SFTP/scp、端口转发和跳板。
- IETF RFC 可用于解释架构和历史协议设计，不据其旧算法列表给出当前安全配置建议。
- 来源与适用范围统一见[来源表](../sources.md)。不使用二手文章作为关键事实的唯一证据。

## 参考内容与采用边界

本次使用系统与协议官方文档，不做平台竞品数据分析。借鉴其技术事实和命令语义，教学顺序、比喻、练习与自测由本项目组织；不复制完整官方教程或网页。

`OpenSSH client server`、`macOS Remote Login`、`Windows OpenSSH Client`、`authorized_keys`、`known_hosts`、`ssh -L`、`RFC 4251`。

## 初步结论

选择“入门 → 实用 → 进阶，排错独立查阅”的结构。避免把公司到家的访问、云服务器、私钥分发和算法调优混进首次登录练习。

- 归属：第 05 篇负责模型与配置示意，第 08 篇负责按症状查阅；不新增独立章节文件。

- 补充核对：OpenSSH 服务端 ListenAddress 与 TCP 转发控制、客户端 -b/-J/ProxyJump、Linux 内核 ip_forward、RFC 1812 路由模型、iproute2 原始查询手册。见 sources.md 的 S20～S24，并复核 S1、S3。
- 主要结论：双网卡监听、应用层 SSH 跳板和系统路由转发要分开；跳板不要求把用户私钥放在 B，也不要求 B 在出口网卡上接收 SSH。
- 验证边界：没有三设备实网测试，服务端配置片段仅按官方语义审校，未运行 sshd -t 或修改系统服务。Linux 查询命令未在 B 执行。
