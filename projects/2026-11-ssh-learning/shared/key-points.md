# SSH 学习关键观点

## 一句话观点

> 登录命令只是入口；读懂它，需要分清操作对象、网络路径和双方身份。

## 关键事实

| 表达 | 来源 | 边界 |
| --- | --- | --- |
| SSH 可以远程执行命令，并承载文件传输和转发 | S1、S5、S6 | 相应功能仍受服务端策略控制 |
| Mac 可通过远程登录接收 SSH 连接 | S7 | 用户和系统策略必须允许 |
| 公钥授权不等于获得管理员权限 | S4、S17 | 权限由目标账号与系统策略决定 |
| 私有 IP 通常不能直接用于互联网入站访问 | S13、S14 | 路由、VPN、NAT 与防火墙会影响路径 |
| 公钥认证时不把用户私钥交给服务器 | S1、S17 | 需信任客户端及私钥保管环境 |

来源编号详见[资料来源](../sources.md)。

## 可复用表达

- 终端是窗口，Shell 解释命令，SSH 建立远程会话。
- 客户端和服务端是角色，普通电脑也能承担服务端角色。
- 登录前问“我要连谁”，登录后问“命令现在在哪执行”。
- known_hosts 帮你认主机，authorized_keys 让主机认用户公钥。
- 127.0.0.1 指自己，具体是谁要看由哪一端使用。
- 私钥口令保护本地文件，账号密码用于服务端认证。
- ListenAddress 选择本机接收连接的地址，客户端 -b 选择本机发起连接的源地址。
- B 有两张网卡，不代表 A、C 已能直接跨网段通信。
- 登录 B、通过 B 跳板登录 C、让 B 做路由器，是三个不同需求。

以上多网卡与转发边界参照来源 S1、S3、S20～S22。

## 风险表达

- 不把“能登录”写成“有全部权限”。
- 不把“密钥登录”写成“绝对免输入”或“绝对安全”。
- 不把“隧道建立”写成“目标网页一定可访问”。
- 不把“自连接成功”写成“公司到家里的网络已打通”。
- 不把上游新版本手册中的所有能力泛化到用户已安装的版本。
