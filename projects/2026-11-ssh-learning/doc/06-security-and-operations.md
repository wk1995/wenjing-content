# 06 安全与运维习惯

SSH 登录成功，只代表当前连接通过了相应检查。要长期用得稳定，还需要管理账号权限、密钥、主机身份和配置变更。本篇用于建立习惯，不要求你立刻修改系统安全策略。

## 权限来自登录的账号

用普通账号登录，就获得这个账号允许的权限。公钥认证不会自动赋予管理员权限。

Mac/Linux 上的 `root` 是高权限账号；`sudo` 是在策略允许时，以其他身份执行指定命令，常见用途是执行管理员操作。遇到“权限不足”先判断当前任务是否应由这个账号完成，不要把所有命令都加 `sudo`。

本教程前几篇的主目录、密钥和文件练习不需要登录 root。

## 服务入口只开放给需要的范围

家里练习时，把 Mac 的远程登录限制到你实际使用的账号。不练习时可以关闭。

监听 `127.0.0.1` 和监听所有网络接口的含义不同。例如本地端口转发绑定到 `127.0.0.1:8080` 时，只接收本机回环访问；换成 `0.0.0.0` 可能让其他可达设备访问该转发端口，还受防火墙等条件约束。

不要为了让命令“好用”，随手扩大监听或用户范围。修改 SSH 端口可以减少部分默认端口扫描噪声，但不能替代认证、权限和更新。

## 密钥按设备区分

给 Mac、Windows 等客户端分别使用可辨认的密钥备注。在目标账号授权时保留清晰记录，某台设备丢失时便于只撤销它。

需要备份私钥时，使用你信任且有访问控制的加密存储方式。公钥可以用于授权交换，私钥文件不能作为配置示例提交到仓库。

如果怀疑私钥泄露，撤销各目标上的对应授权，再换新密钥。只删除本机文件或只更改本机私钥口令，都不能使别人持有的旧副本失效。

## 主机身份改变要先查原因

`REMOTE HOST IDENTIFICATION HAS CHANGED!` 表示当前主机密钥与已有记录不符。可能是系统重装、密钥轮换、地址被重新分配，也可能是连接到了错误目标或遭遇中间人攻击。

处理顺序：

1. 核对目标地址和账号。
2. 通过独立可信渠道取得目标的当前主机公钥指纹。
3. 确认变化原因与新指纹之后，再替换对应旧记录并重新连接。

不要把关闭主机校验或清空整个 `known_hosts` 当作常规解决办法。[排错手册](08-troubleshooting.md)提供针对单个目标的处理说明。

## 修改服务端配置要留退路

当前 Mac 练习优先使用系统设置管理远程登录。本段是将来维护 Linux/Ubuntu 服务器时的阅读材料，不是要求现在执行。

修改认证方式、防火墙或监听端口前，先确认有可用的控制台或其他恢复路径。保留一个已登录会话，改完后另开窗口测试新登录，成功后再结束旧会话。

“改成仅允许密钥登录”的前提是：你已在独立新会话中确认目标账号的公钥认证成功，并知道如何恢复。验证时应确保没有回退到密码登录。

Ubuntu 官方文档提供了这样的配置语法检查命令：

```bash
sudo sshd -t
```

语法检查成功通常没有输出，但这只证明配置通过相应语法检查，不证明外网可达、密钥可用或新会话能登录。

Ubuntu 的配置还可能由 `/etc/ssh/sshd_config.d/` 片段共同决定，不能只看主文件。服务管理命令因系统而异，不要把 Linux 的 `systemctl` 命令套到 macOS 或 Windows。

## 断开 SSH 不等于任务一定继续运行

前台启动的程序可能受会话结束影响。要跑长任务，先学习适合该任务的会话管理或服务管理方式。

`tmux` 可以保留终端会话，系统服务管理工具可用于管理后台服务；它们的安装和配置不属于当前练习。也不要把命令末尾加一个 `&` 理解成“断网后绝对不会停止”。

初学时可以先用三个动作区分会话和程序：

- 命令已经结束、终端正在等输入：用 `exit` 退出当前远程 Shell。
- 前台程序还在持续运行：通常先用 `Control + C` 停止它，再决定是否退出。
- 网络已经断开：重新连接只会建立新会话，原任务是否仍在运行要另行检查；不要直接假定它成功或立刻重复执行会产生副作用的任务。

退出 SSH 不会让目标电脑自动关机；关闭本机终端窗口也不等于远程任务已经妥善结束。

## 不要默认开启代理转发

`ssh -A` 可以把本机认证代理的访问通道转发到远端。远端不会因此直接得到私钥文件，但能访问代理的攻击者可能借它请求签名，进而以你的身份认证到其他目标。

只有明确需要并理解信任边界时再启用。需要跳板连接时，先理解[上一章的 `-J`](05-network-and-tunnels.md)，不必为此把私钥复制到跳板机。

## 自测

1. 密钥登录成功后，就拥有 root 权限了吗？
2. 配置语法检查通过，能否证明新登录肯定成功？
3. 私钥泄露后，只删除自己电脑里的文件够吗？

答案：1. 没有，权限来自目标账号。2. 不能，还要验证网络、服务及实际认证。3. 不够，要撤销目标授权并更换密钥。
