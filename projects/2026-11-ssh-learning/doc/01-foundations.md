# 01 从零认识 SSH

你在公司使用 Mac，家里有 Mac 和 Windows，目前没有远程服务器。这一篇先回答“已经有很多远程工具，为什么还要学 SSH”，再帮你理解一次连接里谁在操作谁，以及命令最终在哪台电脑上执行。

## 有了远程工具 为什么还要学 SSH

SSH 仍然有价值，但你是否需要它，取决于要完成的任务。如果只是偶尔远程打开软件、操作桌面，远程桌面工具就可能已经够用。当你需要查看日志、管理程序、远程开发或自动执行任务时，SSH 会很有用。

SSH 是一种安全通信协议，OpenSSH 是实现它的一套常用软件；远程桌面、文件传输和远程开发工具则是围绕不同任务提供操作界面的产品。它们可以配合使用。

### 先根据任务选择工具

| 你想完成的任务 | 可以从哪类工具开始 | SSH 在其中的作用 |
| --- | --- | --- |
| 看见家里电脑的桌面，用鼠标操作软件 | 远程桌面或屏幕共享 | 这类需求通常不要求你另外配置 SSH |
| 查看日志、检查磁盘、管理运行中的程序 | SSH 客户端与命令行工具 | 登录目标账号，执行对应命令并取得结果 |
| 上传或下载文件 | 文件传输工具 | SFTP 可以通过 SSH 连接传文件 |
| 用本地编辑器开发远程机器上的项目 | 远程开发工具 | 例如 VS Code Remote - SSH 使用 SSH 连接目标 |

OpenSSH 提供远程登录、文件传输和隧道等能力；具体能操作什么，仍受目标账号权限和服务端配置限制。[来源：OpenSSH 官方介绍](https://www.openssh.org/)

### 有些目标电脑没有桌面

服务器可以只运行程序所需的系统组件，不安装图形桌面。只要网络、SSH 服务和登录权限就绪，你仍然可以通过 SSH 查看文件、执行命令和管理程序。

比如家里的某台设备只负责运行一个服务，你想知道它为什么报错，查看日志就可能已经足够，不需要先搭建完整桌面环境。

### 重复操作可以交给脚本

假设你每天都要检查目标机器的磁盘空间。开始时可以亲自登录后运行检查命令；熟悉之后，可以由脚本通过 SSH 执行检查，再保存或处理结果。

这里 SSH 负责远程执行与通信。定时运行、备份策略、重试和告警等，还需要脚本或其他工具来安排。掌握这种文字输入和结果输出的方式，会让以后做自动化更容易。

### 熟悉的图形工具也可能使用 SSH

例如 VS Code 的 Remote - SSH 功能，可以在本地编辑器里打开远程项目，相关命令和部分扩展在远程机器上运行。你面对的是编辑器界面，连接仍需要 SSH 客户端、目标服务和相应登录配置。[来源：VS Code 官方文档](https://code.visualstudio.com/docs/remote/ssh)

因此，理解账号、密钥和连接配置，有助于处理这类工具的连接问题。这个例子只说明 Remote - SSH 的工作方式，不能推定所有远程工具都使用 SSH，也不代表你现在必须安装 VS Code。

### 可以只访问需要的命令或服务

你前面提出过 A 能连接 B、B 能连接 C 的场景。网络与权限允许时，SSH 可以通过 B 跳板登录 C，也可以转发特定服务的访问。这些任务不一定需要传输整个桌面。[第五篇](05-network-and-tunnels.md)会结合双网卡拓扑讲解。

不过，SSH 本身不会自动解决公司到家里的网络连通问题。无论使用终端还是图形客户端，SSH 登录都需要可用的连接路径；具体入口、网络和转发条件仍要确认。

### 对你来说先学到什么程度

你可以继续用熟悉的远程桌面工具操作桌面软件，同时把 SSH 学到能够完成以下任务：

1. 登录目标电脑，并知道命令正在谁那里执行。
2. 分清密码、公钥、私钥，能保存常用连接。
3. 传输文件，并根据报错区分网络、身份和权限问题。

有了这些基础，以后接触服务器、支持 SSH 的 NAS 或远程开发环境时，就能更快上手。接下来先用你已有的电脑理解和练习，不需要先购买服务器。

## 从一个你可能遇到的场景开始

假设家里的 Mac 正在运行一个程序，你想从另一台电脑上查看它的文件、检查程序有没有报错。只要两台电脑的网络能连通，家里的 Mac 开启了 SSH 服务，而且你有登录权限，就可以通过 SSH 操作它。

SSH 是 Secure Shell 的缩写。先把它理解成：通过一条经过身份验证的加密连接，登录另一台电脑并执行命令。它也能为文件传输等功能提供安全通道。

SSH 常见的界面是文字命令行。想看到另一台电脑的桌面、拖动窗口，要另外了解远程桌面或屏幕共享。

## 先会读终端里的符号和路径

本教程的操作命令按行给出。先确认执行位置，再复制一行并回车，读完结果再做下一步。代码块标为配置文件、格式说明或预期输出时，按旁边说明使用。

| 你看到的写法 | 含义 |
| --- | --- |
| 提示符末尾的 `$`、`%`，或 PowerShell 的 `PS ...>` | 表示当前环境在等你输入；复制别处教程时不用把提示符一起复制 |
| `#` 开头的说明行 | 在本教程 Shell 示例中是注释，不是新的操作步骤 |
| `~` 或 PowerShell 中的 `$HOME` | 当前账号的主目录；登录另一台机器后要按那一端的账号理解 |
| `/Users/alice/file.txt` | Mac 上从根目录开始写的绝对路径；示例中的账号名需要替换 |
| `./hello.txt` | 当前目录中的 hello.txt；当前目录可以用 `pwd` 查看 |
| `..` | 上一级目录；例如 `cd ..` 是进入上一级 |
| `"带空格的文件名.txt"` | 引号把包含空格的路径作为一个参数传入，避免被拆成几个参数 |

本教程大多数路径采用 Mac/Linux 的 `/` 写法；PowerShell 里常见 Windows 路径使用 `\`。两端的主目录和文件并不会因为建立 SSH 连接就自动合并。

后面会用到的基础命令：

| 命令 | 在 Mac Shell 中做什么 |
| --- | --- |
| `pwd`、`ls` | 查看当前目录、列出文件；`ls -la` 还可以列出隐藏项和详细信息 |
| `cd 路径` | 改变当前目录；只改变该终端会话的当前位置 |
| `cat 文本文件` | 显示指定文本文件内容；后文只要求查看公钥，不要求显示私钥 |
| `mkdir -p 路径` | 按需创建目录；目录已存在时保留它 |
| `chmod` | 调整文件权限，后面会解释具体数字 |
| `exit` | 退出当前 Shell；在 SSH 登录会话里通常用于退出远程 |

`Control + C` 通常用来中止当前前台命令；Mac 的 `Command + C` 用于复制文本。后文编辑器保存使用的也是 Control 键，不要混淆。

## 先认识六个词

| 名称 | 含义 | 你可以怎样理解 |
| --- | --- | --- |
| 终端 Terminal | 输入命令、显示输出的窗口 | Mac 上的“终端”App |
| Shell | 解释并执行命令的程序 | 常见的有 zsh、bash，Windows 也有 PowerShell |
| SSH | 安全通信与远程登录协议 | 两端如何连接、验证身份和通信的规则 |
| OpenSSH | 实现 SSH 的一套软件 | 包含登录、生成密钥、传文件等工具 |
| `ssh` | 发起 SSH 连接的客户端程序 | 你会输入的那条命令 |
| `sshd` | 接收 SSH 连接的服务端程序 | 对方电脑上的接待程序 |

“协议”和“软件”可以这样区分：协议规定怎么沟通，软件负责真正完成沟通。SSH 有多种实现，本教程以 OpenSSH 为主。

## 服务器可以是一台普通电脑

```text
你正在使用的电脑                     你要操作的电脑
SSH 客户端 ───── 加密连接 ─────→ SSH 服务端
发起登录                           接收连接并验证登录资格
```

这里的“客户端”和“服务端”描述角色。家里的 Mac 接收连接时就是服务端；它主动连接其他机器时又可以成为客户端。

云服务器是另一种常见目标。它可以理解成远程机房里供你使用的一台计算机。本教程的前几篇不需要购买它。

## 读懂第一条命令

格式说明，不要原样执行中文占位符：

```text
ssh 对方账号@对方地址
```

假设家里 Mac 的账号是 `alice`，局域网地址是 `192.168.1.50`，命令就写成：

```bash
ssh alice@192.168.1.50
```

这是虚构示例。实际操作时，账号和地址都要替换。

- `alice` 是目标电脑上的账号，不一定和发起连接的电脑账号相同。
- `@` 把账号和地址分开。
- 地址可以是 IP，也可以是可解析到目标的主机名或域名。

如果服务端指定使用 2222 端口：

```bash
ssh -p 2222 alice@192.168.1.50
```

可以把 IP 想成楼的地址，端口想成楼里的服务窗口。这个比喻只用于区分两者。SSH 的常见默认端口是 22，端口号本身不代表权限或密码。

## 两个方向的身份验证

连接时需要分别回答：

1. 你的客户端要确认：对面是不是你想连接的那台电脑？这涉及主机密钥、指纹和 `known_hosts`。
2. 服务端要确认：你有没有资格登录这个账号？这涉及密码、公钥或其他认证方式。

第一次连接时询问是否信任主机，与随后询问登录密码，是两回事。[第三篇](03-key-authentication.md)会展开解释。

## 登录后，命令在哪执行

```text
打开自己的终端 → 命令在本机执行
SSH 登录成功   → 命令在目标电脑上执行
输入 exit 退出 → 回到原来的终端会话
```

例如登录另一台 Mac 后输入 `ls`，列出的是另一台 Mac 当前目录中的文件。

如果连接的是自己的 `127.0.0.1`，依然建立了 SSH 会话，只是客户端和服务端恰好在同一台机器上。

## 今天可以完成的小练习

在 Mac 按 `Command + 空格`，搜索“终端”，逐条输入：

```bash
ssh -V
whoami
hostname
pwd
```

| 命令 | 作用 | 结果怎么读 |
| --- | --- | --- |
| `ssh -V` | 显示 SSH 客户端版本，注意大写 V | 出现 OpenSSH 版本说明找到了客户端 |
| `whoami` | 显示当前账号的短名称 | 以后登录自己时用这个账号名 |
| `hostname` | 显示本机主机名 | 用来帮助判断当前在哪台机器上 |
| `pwd` | 显示当前工作目录 | 命令默认操作的位置 |

这些命令不需要远程服务器，也不会开启 SSH 服务。版本号和输出不需要与别人完全相同。

## 自测

1. 打开终端是否就代表进入了远程电脑？
2. Windows 可以当客户端，Mac 可以当服务端吗？
3. `ssh bob@192.168.1.20` 里的 `bob` 是哪台电脑上的账号？
4. 登录另一台电脑后，`pwd` 显示哪台电脑的目录？
5. 只想远程用鼠标操作家里的桌面软件，是否必须另外学会并配置 SSH？
6. VS Code Remote - SSH 有图形界面，是否就不再需要 SSH 服务和登录配置？

答案：1. 没有，还需要连接成功。2. 可以，前提是相应软件、服务、权限和网络就绪。3. 目标电脑。4. 目标电脑。5. 不一定，远程桌面工具可能已满足需求。6. 仍然需要，它通过 SSH 连接远程环境。
